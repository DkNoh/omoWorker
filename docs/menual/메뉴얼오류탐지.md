## 1. 확인된 위반 (3건)

### 1.3 중첩 모달 — Notify.confirm backdrop 클릭 시 이벤트 소실

**규칙**: CoreUI 공식 계약상 `multiple modals cannot be open simultaneously`. 중첩 모달은 비공식 동작에 의존.
**위반**: `modal-base.html:36`의 `data-coreui-backdrop="static"` 비즈니스 모달 위에 `notify.js`가 `#custom-modal-overlay`(별도 CoreUI 모달)를 `document.body`에 주입하여 중첩.

**재현 시나리오**:
1. 상세 모달(삭제 모드) → 삭제 버튼 클릭 → `CommonUtils.confirm()` → 확인 모달 표시
2. **배경 클릭** → CoreUI가 모달을 닫음
3. `notify.js:139`의 `closeAndNext()`는 확인·취소·ESC 버튼에만 연결됨 → `_showing`이 `true`로 고정
4. 다시 삭제 버튼 클릭 → 확인 요청이 큐에 쌓이지만 `_showing=true`로 인해 표시되지 않음
5. 큐가 영구적으로 블록됨

**영향 범위**: `customer-search.js:175`, `notice-popup.js:209`, `notice.js:166`, `message-edit.js:112`, `campaign-register.js:132`, `system/list-crud.js:222`, `editor-popup.js:116,142` — 7개 화면이 모달 내부에서 `confirm()` 사용.

**추가 결함**: ESC 이벤트 리스너(`notify.js:150-157`)가 `closeAndNext()` 내부에서 `removeEventListener`를 호출하지 않아, 모달이 여러 번 열릴 때마다 리스너가 누적됨.

**대응 파일**: `src/main/resources/static/js/common/notify.js`

**해결 상태 (2026-07-29)**: ✅ 해결됨

**적용 내용**:
- SweetAlert2 11.26.25를 `static/lib/sweetalert2/11.26.25/`에 폐쇄망 자산으로 반입
- `notify.js`의 `#custom-modal-overlay` CoreUI 모달 렌더러를 SweetAlert2 `Swal.fire()`로 교체
- backdrop/ESC/cancel/close 모든 dismiss 경로를 `onCancel` 1회 호출로 수렴
- `finally`에서 `_showing=false` + `_processQueue()` 정확히 1회 실행 → 큐 영구 블록 해결
- 직접 `document.addEventListener('keydown', escHandler)` 제거 → ESC 리스너 누적 해결
- `admin-ui-bridge.css`에 `sms-swal-*` bridge 클래스 추가, `--sms-z-overlay`로 CoreUI 모달 위 표시
- `NotifySweetAlertContractTest` (10개 테스트)로 계약 고정

**검증**:
- `JAVA_HOME=$(/usr/libexec/java_home -v 21) mvn -Dtest=NotifySweetAlertContractTest test` — 10/10 통과
- 정적 샘플 `modal-patterns.html` Chrome QA — confirm/cancel/ESC/backdrop/큐/중첩 모달 검증

### 1.1 PAGE_AUTH strict comparison 누락

**규칙**: `auth.xxx === true` (strict comparison + fail-closed)
**위반**: `!== true` 비교 사용

```javascript
// customer-search.js:90
if (deleteBtn) deleteBtn.hidden = state.mode !== 'update' || !(window.PAGE_AUTH || {}).delete;
```

매뉴얼이 명시한 올바른 패턴:

```javascript
// auth-page_manual.md §5.2
const canDelete = state.mode === 'update' && auth.delete === true;
```

현재 코드는 `delete`가 문자열 `"false"`일 때 truthy로 처리될 수 있습니다.
서버 Interceptor가 API 접근을 다시 차단하므로 **UI 권한 표시 문제**입니다.

**대응 파일**: `src/main/resources/static/js/sms/customer-search.js`

### 1.2 z-index magic number

**규칙**: `z-index: 9999` 같은 magic number 금지, `--sms-z-*` 토큰만 사용
**위반**: `container.style.zIndex = '9999'`

```javascript
// notify.js:182
container.style.zIndex = '9999';
```

매뉴얼이 정의한 토큰:

| 토큰 | 값 | 용도 |
|------|-----|------|
| `--sms-z-toast` | `1080` | 토스트 알림 |
| `--sms-z-overlay` | `1100` | 전역 spinner overlay |

**대응 파일**: `src/main/resources/static/js/common/notify.js`
