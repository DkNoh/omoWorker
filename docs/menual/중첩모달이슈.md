# 중첩 모달 이슈 — Notify.confirm backdrop 클릭 시 큐 영구 블록

> 기록 성격: SweetAlert2 전환 당시의 문제 분석·해결·브라우저 검증 기록이다. 현재 사용법은 `common-js_manual.md`와 `coreui_manual.md`를 우선한다.

> 작성일: 2026-07-29
> 원인: CoreUI `multiple modals cannot be open simultaneously` 계약 위반
> 해결: SweetAlert2 11.26.25 기반 공통 팝업으로 교체

---

## 1. As-Is (기존 구조)

### 1.1 아키텍처

```
document.body
├── #form-modal (CoreUI 모달, data-coreui-backdrop="static")
│   └── 삭제 버튼 → CommonUtils.confirm()
│
└── #custom-modal-overlay (notify.js 가 주입한 별도 CoreUI 모달)
    ├── backdrop (static)
    ├── 확인 버튼
    └── 취소 버튼
```

**문제**: `notify.js`가 `#custom-modal-overlay`라는 **별도 CoreUI 모달**을 `document.body`에 주입했다.
CoreUI 공식 계약상 `multiple modals cannot be open simultaneously`이므로,
비즈니스 모달 위에 확인 모달이 쌓이면 비공식 동작에 의존하게 된다.

### 1.2 재현 시나리오

1. 상세 모달(삭제 모드) 열기 → `data-coreui-backdrop="static"` 비즈니스 모달 표시
2. 삭제 버튼 클릭 → `CommonUtils.confirm()` → `notify.js`가 `#custom-modal-overlay` 주입
3. **배경 클릭** → CoreUI가 모달을 닫으려 함
4. `notify.js:139`의 `closeAndNext()`는 확인·취소·ESC 버튼에만 연결됨
5. backdrop 클릭 시 `_showing`이 `true`로 고정 → 상태 해제 경로 없음
6. 다시 삭제 버튼 클릭 → 확인 요청이 큐에 쌓이지만 `_showing=true`로 표시되지 않음
7. **큐가 영구적으로 블록됨**

### 1.3 추가 결함

- **ESC 리스너 누적**: `notify.js:150-157`의 `document.addEventListener('keydown', escHandler)`가
  `closeAndNext()` 내부에서 `removeEventListener`를 호출하지 않아,
  모달이 여러 번 열릴 때마다 리스너가 누적됨
- **7개 화면 영향**: `customer-search.js:175`, `notice-popup.js:209`, `notice.js:166`,
  `message-edit.js:112`, `campaign-register.js:132`, `system/list-crud.js:222`,
  `editor-popup.js:116,142` — 모든 화면이 모달 내부에서 `confirm()` 사용

### 1.4 코드 구조 (기존 notify.js)

```javascript
// notify.js (기존, ~240 라인)
const _render = () => {
    // 1. #custom-modal-overlay DOM 생성 (document.body 주입)
    // 2. CoreUI Modal.getOrCreateInstance() 로 모달 인스턴스화
    // 3. backdrop 클릭 → closeAndNext() 호출 (확인/취소/ESC 버튼에만 연결)
    // 4. ESC keydown listener 등록 (누적 문제)
    // 5. backdrop 클릭 시 _showing 고착 → 큐 영구 블록
};

// DOM 생성 로직
const overlay = document.createElement('div');
overlay.id = 'custom-modal-overlay';
overlay.className = 'modal fade custom-modal-overlay';
overlay.setAttribute('data-coreui-backdrop', 'static');
overlay.setAttribute('tabindex', '-1');
overlay.innerHTML = `...확인/취소 버튼...`;
document.body.appendChild(overlay);

// ESC 리스너 누적
document.addEventListener('keydown', escHandler);  // remove 안 함
```

## 2. To-Be (해결 후 구조)

### 2.1 아키텍처

```
document.body
├── #form-modal (CoreUI 모달, data-coreui-backdrop="static")
│   └── 삭제 버튼 → CommonUtils.confirm()
│
└── .swal2-container (SweetAlert2가 자체 관리하는 팝업)
    ├── backdrop (SweetAlert2 내부)
    ├── 확인 버튼 (.sms-swal-confirm)
    └── 취소 버튼 (.sms-swal-cancel)
```

**핵심 변경**: SweetAlert2가 **자체 DOM/backdrop/focus/ESC 처리**를 담당하므로,
CoreUI 모달과의 중첩 문제가 완전히 소멸된다.

### 2.2 동작 흐름

```
1. Notify.confirm(msg, callback, title, onCancel) 호출
2. _enqueue() → _queue.push({ type:'confirm', msg, title, onConfirm:callback, onCancel })
3. _processQueue() → _render(item)
4. Swal.fire({
       title: '알림',
       text: msg,           // ← text 옵션 (XSS 방지)
       showCancelButton: true,
       confirmButtonText: '확인',
       cancelButtonText: '취소',
       customClass: { popup: 'sms-swal-popup', ... }
   })
5. 확인 클릭 → result.isConfirmed=true → onConfirm() 호출
6. 취소/ESC/backdrop 클릭 → result.isConfirmed=false → onCancel() 호출
7. finally() → _showing=false → _processQueue() → 다음 큐 항목 처리
```

### 2.3 코드 구조 (현재 notify.js)

```javascript
// notify.js (현재, 213 라인)
const _render = ({ type, msg, title, onConfirm, onCancel }) => {
    // SweetAlert2 가드가 없으면 fail-closed
    if (!window.Swal || typeof window.Swal.fire !== 'function') {
        _showing = false;
        if (type === 'confirm' && typeof onCancel === 'function') onCancel();
        _processQueue();
        return;
    }

    Swal.fire({
        title: title || '알림',
        text: msg || '',              // ← text 옵션 (HTML 이스케이프 자동)
        showCancelButton: isConfirm,
        confirmButtonText: '확인',
        cancelButtonText: '취소',
        buttonsStyling: false,
        allowOutsideClick: true,
        allowEscapeKey: true,
        returnFocus: true,
        customClass: {
            container: 'sms-swal-container',
            popup: 'sms-swal-popup',
            title: 'sms-swal-title',
            htmlContainer: 'sms-swal-message',
            actions: 'sms-swal-actions',
            confirmButton: 'sms-swal-confirm',
            cancelButton: 'sms-swal-cancel'
        }
    }).then((result) => {
        if (result.isConfirmed) {
            return safeInvoke(onConfirm);
        }
        if (isConfirm) {
            return safeInvoke(onCancel);   // ← 모든 dismiss 경로가 onCancel 으로 수렴
        }
        return Promise.resolve();
    }).finally(() => {
        _showing = false;
        _processQueue();                   // ← 정확히 1회 실행, 큐 영구 블록 해결
    });
};
```

|------|-------------|-------------|

| **라인 수** | ~240 | 213 |

### 3.3 핵심 해결 포인트

#### (1) 큐 영구 블록 → finally 기반 해제

```javascript
// As-Is: backdrop 클릭 시 closeAndNext() 미호출 → _showing=true 고착
// backdrop 클릭 → CoreUI 모달 닫힘 → closeAndNext() 호출 안 됨 → _showing 고착

// To-Be: SweetAlert2 dismiss → .then() → .finally() → _showing=false → _processQueue()
Swal.fire({...}).then(result => { ... }).finally(() => {
    _showing = false;
    _processQueue();   // ← 모든 종료 경로에서 정확히 1회 실행
});
```

#### (2) ESC 리스너 누적 → SweetAlert2 내장

```javascript
// As-Is: 매번 열릴 때마다 addEventListener 누적
document.addEventListener('keydown', escHandler);  // remove 안 함

// To-Be: SweetAlert2가 ESC 처리를 자체 담당
// allowEscapeKey: true 설정만으로 ESC dismiss 동작
```

#### (3) 중첩 모달 문제 → SweetAlert2 독립 DOM

```javascript
// As-Is: #custom-modal-overlay가 CoreUI 모달 위에 쌓임
// CoreUI: "multiple modals cannot be open simultaneously"

// To-Be: SweetAlert2가 .swal2-container 자체 관리
// CoreUI 모달과 독립적인 DOM 트리 → 중첩 문제 소멸
```

#### (4) dismiss 경로 수렴

```javascript
// As-Is: 확인/취소/ESC 버튼에만 closeAndNext() 연결
// backdrop 클릭 → _showing 고착

// To-Be: SweetAlert2 result.isConfirmed 판별
// isConfirmed=true → onConfirm()
// isConfirmed=false (cancel/backdrop/ESC/close 모두) → onCancel()
```
