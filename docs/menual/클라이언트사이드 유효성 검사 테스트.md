# 클라이언트사이드 유효성 검사 이슈 — 필수값 오류 메시지 미표시

> 기록 성격: FieldFormat 검증 오류 수정 당시의 재현·회귀 검증 기록이다. 현재 사용법은 `just-validate_manual.md`와 `common-js_manual.md`를 우선한다.

> 작성일: 2026-07-30
> 원인: JustValidate 4.3.0 `revalidate()`의 전체 폼 오류 라벨 미렌더링 결함
> 해결: `FieldFormat.validateForm()`을 selector 기반 per-field `revalidateField()` 방식으로 교체

---

## 1. As-Is (기존 구조)

### 1.1 아키텍처

```text
CRUD 화면
├── <form id="detail-form" 또는 id="dept-form">
│   ├── [data-validate="required|..."] 필드
│   └── FieldFormat.applyFieldFormats(form)
│       └── buildValidator(form)
│           └── validator.addField('#' + el.id, rules)
│
└── 저장 버튼 (form 바깥 modal footer)
    └── save()
        └── FieldFormat.validateForm(form)
            └── validator.revalidate()
```

스캐폴드 CRUD 화면은 화면별로 `new JustValidate()`를 직접 생성하지 않는다.
폼 필드에 `data-validate`를 선언하고, 공통 `FieldFormat` 모듈이 규칙 등록과 검증 실행을 담당한다.

### 1.2 기존 저장 흐름

```javascript
const save = async () => {
    const form = document.querySelector('#detail-form');
    if (typeof FieldFormat !== 'undefined' && !await FieldFormat.validateForm(form)) return;

    const payload = FormBinder.toObject('#detail-form');
    // create/update API 호출
};
```

```javascript
// field-format.js 기존 구현
const validateForm = (root) => {
    const validator = validators.get(root);
    if (!validator) {
        return Promise.resolve(true);
    }
    return validator.revalidate();
};
```

### 1.3 재현 시나리오

1. `samples/list-crud.html`을 연다.
2. **등록** 버튼을 눌러 신규 등록 모달을 연다.
3. `depCode`, `depNm`을 입력하지 않고 **저장** 버튼을 누른다.
4. JustValidate 내부 상태에서는 두 필드가 invalid로 판정된다.
5. 첫 invalid 필드로 포커스가 이동하지만 `.just-validate-error-label`이 렌더링되지 않는다.
6. 저장은 중단되지만 사용자는 중단 원인을 화면에서 확인할 수 없다.

### 1.4 신규/수정 모드 차이처럼 보인 이유

생성 화면의 신규/수정 저장 로직은 모두 동일한 `FieldFormat.validateForm(form)`을 호출한다.
모드별 검증 분기가 있는 것이 아니다.

수정 모드에서는 기존 값이 채워진 필드를 사용자가 지우는 과정에서 `input` 이벤트가 발생한다.
JustValidate는 이 이벤트로 해당 필드를 touched 상태로 검증하여 오류 메시지를 먼저 렌더링할 수 있다.
반면 신규 모드의 untouched 빈 필드는 저장 시 `revalidate()` 경로만 타므로,
라이브러리 결함이 그대로 노출되어 모드별 동작 차이처럼 보인다.

### 1.5 근본 원인

JustValidate 4.3.0의 `revalidate()`는 전체 폼의 유효성 결과와 포커스는 갱신하지만,
제출되지 않았고 untouched 상태인 필드의 오류 라벨을 강제로 렌더링하지 못하는 알려진 결함이 있다.

동일 증상은 upstream issue `horprogs/Just-validate#155`에도 보고되어 있다.

```text
revalidate()
├── 필드 값 검증                    → 실행됨
├── validator.isValid 갱신          → 실행됨
├── 첫 invalid 필드 focus           → 실행됨
└── 오류 label/class 강제 렌더링    → 실행되지 않음
```

## 2. To-Be (해결 후 구조)

### 2.1 아키텍처

```text
FieldFormat.applyFieldFormats(form)
└── buildValidator(form)
    └── validator.addField('#' + el.id, rules)

저장 버튼
└── FieldFormat.validateForm(form)
    ├── 현재 [data-validate] 필드 재조회
    ├── validator.revalidateField('#' + el.id) 병렬 실행
    ├── 각 필드 오류 label/class 렌더링
    ├── 첫 invalid 필드 명시적 focus
    └── results.every(Boolean) 반환
```

**핵심 변경**: 전체 폼 `revalidate()` 대신 공개 per-field API인 `revalidateField()`를 사용한다.
이 메서드는 각 필드에 대해 기존 스타일과 라벨을 정리한 뒤 오류를 강제로 다시 렌더링한다.

### 2.2 현재 코드

```javascript
/** root 폼의 검증을 실행한다. 검증기가 없으면 통과(true). 반환: Promise<boolean> */
const validateForm = (root) => {
    const validator = validators.get(root);
    if (!validator) {
        return Promise.resolve(true);
    }
    const fields = Array.from(root.querySelectorAll('[data-validate]'));
    if (fields.length === 0) {
        return Promise.resolve(true);
    }
    // JustValidate 4.3.0 revalidate()는 포커스만 하고 에러 라벨을 렌더링하지 않는
    // upstream 결함(horprogs/Just-validate#155)이 있으므로, per-field revalidateField로
    // 각 필드를 개별 검증(clear + render)한 뒤 첫 invalid 필드를 명시적으로 포커스한다.
    return Promise.all(fields.map(el => validator.revalidateField('#' + el.id)))
        .then(results => {
            const firstInvalid = results.indexOf(false);
            if (firstInvalid !== -1) {
                fields[firstInvalid].focus();
            }
            return results.every(Boolean);
        });
};
```

### 2.3 동작 흐름

```text
1. 저장 버튼 클릭
2. FieldFormat.validateForm(form) 호출
3. WeakMap에서 form의 JustValidate 인스턴스 조회
4. form 내부 [data-validate] 필드 목록 조회
5. 각 필드에 revalidateField('#' + el.id) 호출
6. 각 Promise<boolean> 결과를 원래 필드 순서대로 수집
7. 첫 false 결과의 필드에 focus()
8. results.every(Boolean) 반환
9. false이면 저장 중단, true이면 payload 생성 및 API 호출
```

### 2.4 selector 키 일치가 필요한 이유

`buildValidator()`는 필드를 다음과 같이 **문자열 selector**로 등록한다.

```javascript
validator.addField('#' + el.id, rules);
```

따라서 재검증도 동일한 키 형태를 사용해야 한다.

```javascript
// 잘못된 1차 시도
validator.revalidateField(el);              // DOM Element 전달

// 최종 수정
validator.revalidateField('#' + el.id);     // 등록 시 사용한 selector와 동일
```

JustValidate의 `fieldIds` Map은 `addField()`에 전달된 값을 키로 사용한다.
DOM Element를 전달하면 `'#depCode'` 문자열 키와 일치하지 않아
`Field not found. Check the field selector.` 오류가 발생하고 `Promise.all()`이 reject된다.

## 3. 해결 내용 상세

### 3.1 변경된 파일

| 파일 | 변경 내용 |
|------|-----------|
| `static/js/common/field-format.js` | 전체 폼 `revalidate()`를 selector 기반 per-field `revalidateField()`로 교체하고 첫 invalid 필드 포커스 추가 |
| `docs/menual/just-validate_manual.md` | `FieldFormat.validateForm()` 내부 동작과 JustValidate 4.3.0 결함 설명 정정 |
| `docs/menual/common-js_manual.md` | 공통 FieldFormat 검증 흐름을 per-field 방식으로 정정 |

### 3.2 변경 요약

| 항목 | As-Is (기존) | To-Be (현재) |
|------|-------------|-------------|
| **검증 단위** | 전체 폼 `revalidate()` 1회 | 각 `[data-validate]` 필드 `revalidateField()` |
| **오류 라벨** | untouched 빈 필드에서 미표시 가능 | 각 invalid 필드 아래 강제 렌더링 |
| **포커스** | 라이브러리 내부 동작 의존 | 결과 배열의 첫 invalid 필드에 명시적 `focus()` |
| **필드 키** | 전체 폼이라 직접 키 조회 없음 | 등록과 동일한 `'#' + el.id` selector 사용 |
| **반환 계약** | `Promise<boolean>` | `Promise<boolean>` 유지 |
| **화면 호출부** | `FieldFormat.validateForm(form)` | 변경 없음 |
| **서버 검증** | 서버 `@Valid`가 최종 권위 | 변경 없음 |

### 3.3 핵심 해결 포인트

#### (1) 오류 라벨 미표시 → per-field 강제 렌더링

```javascript
// As-Is
return validator.revalidate();

// To-Be
return Promise.all(fields.map(el => validator.revalidateField('#' + el.id)));
```

#### (2) 포커스 동작 명시화

```javascript
const firstInvalid = results.indexOf(false);
if (firstInvalid !== -1) {
    fields[firstInvalid].focus();
}
```

#### (3) 전체 폼 결과 계약 유지

```javascript
return results.every(Boolean);
```

기존 호출자는 여전히 `await FieldFormat.validateForm(form)` 결과만 확인하므로 수정할 필요가 없다.

#### (4) 검증기 또는 검증 필드가 없는 화면의 기존 동작 유지

```javascript
if (!validator) return Promise.resolve(true);
if (fields.length === 0) return Promise.resolve(true);
```
