## 4. 반입 참고사항

- **samples/ 는 dev/local 전용 참조 화면**이다. 운영(prod) 노출 차단은 반입 측에서 별도 처리한다(차단 인터셉터 미포함). samples를 prod에 배포하지 않거나 WAS/웹서버 단에서 `/samples/**`를 막는다.
- **스캐폴드 실행 소스는 운영 배포 반입 대상이 아니다.** `ScaffoldController` 등은 `@Profile("local")`이고 prod WAR 빌드에서 제외된다. 다만 폐쇄망에서 신규 화면 생성 기능을 사용할 때는 생성기 소스·템플릿·테스트·golden 파일을 개발 도구 묶음으로 선택 반입하고, 운영 WAR에는 포함하지 않는다.
- **`opencode.json` / `.opencode/*` 는 개발 도구(에이전트) 설정**이라 환경에 따라 다르다. 폐쇄망 에이전트 구성이 다르면 반입하지 않아도 된다.
- **삭제 파일(3장)은 폐쇄망 저장소에서도 반드시 삭제**한다. 특히 `templates/system/message-edit.html`, `templates/sms/campaign-register.html`은 `static/samples/`로 대체되었으므로 둘이 공존하면 혼선이 생긴다.
- **프래그먼트 `toast-grid.html`은 하위호환**이다. 기존 무인자 호출 화면(발송이력/고객검색/공지)은 그대로 동작하고, 다중 그리드 화면만 인자를 전달한다.
- **field-format.js의 JustValidate 한글 메시지**는 `data-validate`를 쓰는 모든 화면·스캐폴드 생성물에 자동 반영된다. 별도 언어팩 파일은 없다(JustValidate 4.x는 로케일 미지원).

### 5.3 추가 반입 시 주의사항

- **SweetAlert2 관련 파일은 한 묶음으로 반입**한다. 라이브러리 3개, `MANIFEST.md`, `defaultLayout.html`, `notify.js`, `admin-ui-bridge.css`, `NotifySweetAlertContractTest.java` 중 일부만 반입하면 알림이 표시되지 않거나 스타일/로드 순서 계약이 깨진다.
- **스캐폴드 개발 도구는 한 묶음으로 선택 반입**한다. `scaffold.js`, `MapperXmlViewFactory.java`, `scaffold-templates/**/*.tpl`, `toast-grid.html`, `ScaffoldTemplateTest.java`, `ScaffoldOutputGoldenTest.java`, 대표 Golden 49개가 같은 생성 계약을 공유한다. Golden은 LIST·EXCEL·CRUD·전체 옵션의 전체 산출물과 DB별 Mapper XML만 유지한다. 이 묶음은 폐쇄망에서 신규 화면을 생성할 때만 필요하며 운영 WAR에는 포함하지 않는다.
- **발송이력 CRUD 묶음도 함께 반입**한다. Controller/DTO/Mapper/Service/VO/XML/HTML/JS/테스트/메뉴 seed 중 일부만 반입하면 API, 화면 또는 권한이 불일치한다.
- **Oracle 볼륨은 새로 만들거나 초기화하지 않는다.** 폐쇄망 환경에 기존 데이터가 있으면 `smstest-v3_sms-oracle-data` 외부 볼륨 연결을 먼저 확인한다. 관리자 계정과 SMS 애플리케이션 계정 비밀번호는 별도 환경변수로 주입한다.
- **`.opencode/*`, `opencode.json`은 실행 코드가 아닌 개발 도구 설정**이다. 폐쇄망의 모델 ID와 공급자 구성이 다르면 반입하지 않거나 현지 설정에 맞춰 별도로 병합한다.
- Golden 범위 축소로 `scaffold-golden/keyword_*.txt` 11개와 DB2·MSSQL·PostgreSQL의 Mapper XML 이외 중복 Golden 33개를 삭제했다. 앞의 3장에 적힌 기존 삭제 대상도 그대로 유효하다.
- 반입 완료 후 최소 검증은 `mvn test`와 `mvn -DskipTests package`다.

### 6.3 이 개선분 반입 시 주의사항

- **현재 개발자가 수정해 사용 중인 생성 화면에는 새 템플릿을 일괄 적용하지 않는다.** 새 `.tpl` 계약은 앞으로 최초 생성하는 화면에만 적용한다. 재생성할 때는 기존 수정본을 병합하거나 보존하지 않고 폐기한 뒤 신규 생성한다.
- 기존 화면을 의도적으로 교체할 때도 `domainClass`는 기존 클래스명과 대소문자를 정확히 맞춘다. 대소문자만 다른 이름은 `ScaffoldFileApplier`가 미리보기부터 차단하며, 이는 정상적인 동일 경로 덮어쓰기와 별개다.
- **메뉴 캐시 개선은 관련 소스와 테스트를 함께 반입**한다. `MenuCacheRevision.java`, `GlobalModelAdvice.java`, `MenuManageService.java` 중 일부만 반입하면 revision 증가 또는 세션 무효화 한쪽이 빠져 기존 로그인 사용자의 LNB·화면 권한이 갱신되지 않는다.
- 메뉴 revision은 현재 애플리케이션 프로세스 메모리 기준이다. 다중 WAS에서는 공유 revision 저장소나 노드 간 무효화 전파를 별도로 구성해야 한다.
- 역할 배정 변경은 메뉴 CRUD revision 대상이 아니다. 사용자 역할 자체가 변경된 경우에는 현재 정책대로 재로그인하여 세션의 역할 목록을 갱신한다.
- 단순 쿼리로 안전 판정되지 않은 JOIN·서브쿼리·집계·`DISTINCT`·`GROUP BY`·`HAVING`·`UNION`은 기존 외부 검색 조건과 래퍼 COUNT를 유지한다. 수동으로 직접 COUNT로 바꾸지 않는다.
- 이 개선분까지 반입한 뒤 최소 검증은 `mvn test`와 `mvn -DskipTests package`다.

## 9. 폐쇄망 재생성 화면 제외 (2026-08-03 추가)

`SMS_HISTORY`와 공지사항 화면은 폐쇄망에서 스캐폴드로 다시 생성하므로 Controller·DTO·Service·Mapper·VO·Mapper XML·HTML·JS와 해당 화면 전용 테스트를 반입하지 않는다. 폐쇄망 저장소에 기존 파일이 있으면 `docs/반입리스트.txt`의 **삭제할 파일** 목록에 따라 제거한다. `ConventionTest`에 있던 공지사항 수동 소유 파일 검사도 삭제된 화면을 참조하지 않도록 제거한다.

재생성에 필요한 스캐폴드 엔진, 생성 템플릿, golden 파일 및 `src/main/resources/scaffold-cases/sms_history.json`은 유지한다. 공통 메뉴·권한 코드와 다른 화면에서 함께 사용하는 공통 자산도 삭제하지 않는다.

### 10.1 반입·운영 주의사항

- `docs/반입리스트.txt`와 Git 변경 파일만 기준으로 선별 반입하지 않는다. `ScaffoldDialect.java`는 증분 변경이 없어도 스캐폴드 엔진의 필수 의존성이다.
